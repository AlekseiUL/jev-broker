# Как агенту пользоваться JEV Broker

У тебя есть один инструмент `mcp__jev_broker__evaluate`. Это не готовый список вопросов: **ты сам** выбираешь задачу, материал и критерии. JEV быстро выдаёт короткие вероятностные суждения; он не ищет источники, не объясняет всё исследование и не заменяет проверку фактов.

## Когда он поможет

Перед вызовом ответь себе: «Какое следующее решение изменится после этой оценки?» Если ничего не изменится, не вызывай инструмент. Подходящие задачи — проверить один признак, распределить найденные материалы по твоим категориям, ранжировать похожие находки по явно описанной шкале. Источники и права на их обработку проверяются до вызова; JEV не выдаёт разрешений на чтение или публикацию.

| Режим | Передаёшь | Получаешь | Пример решения |
|---|---|---|---|
| `noul` | вопрос с ответом да/нет; при желании описания `true` и `false` | вероятность «да» от 0 до 1 | «Это действительно жалоба на задержку ответа?» |
| `choice` | вопрос и свои варианты `options` | выбранный вариант и вероятности | «Это жалоба, вопрос, новость или `none_unknown`?» |
| `score` | вопрос и упорядоченный `rubric` от низкого уровня к высокому | балл относительно **этой** шкалы и вероятности уровней | «Насколько этот сигнал пригоден для исследования?» |

Для `choice` добавляй `none_unknown`, если ни один вариант может не подойти. `min_confidence` можно задать для `noul` и `choice`; тогда низкая уверенность обозначается как неопределённость, а не как принудительное решение. Для `score` балл не равен проценту качества: всегда читай подписи уровней.

## Контракт инструмента

`evaluate` принимает `questions` — объект с именованными решениями. Каждый вопрос содержит `mode`, `task` и поля режима: необязательные `criteria` для `noul`, обязательные `options` для `choice`, обязательный упорядоченный `rubric` из минимум двух уровней для `score`. `task` может быть текстом или структурированным описанием. Вместе с вопросами передай либо один непустой `state`, либо `items` — именованные непустые записи; при `items` общий `state` необязателен и выступает контекстом для каждой записи.

Один вызов без `items` — один запрос к платной модели. При `items` каждый элемент оценивается отдельным платным запросом с одинаковым набором вопросов. Смешивать три режима в одном вызове можно. Делай партии обозримыми: большая партия идёт последовательно, может упереться в тайм-аут и не вернуть часть результатов. Не повторяй автоматически неясно завершившийся платный вызов.

Технические пределы этой версии: до 8 `items` (каждый — отдельный платный запрос), до 64 вопросов, до 1 МиБ входного JSON и до 4 МиБ исходящего JSON на вызов; для `choice` — не более 255 вариантов, для `score` — 2–10 уровней. Профиль может зарезервировать не более 32 платных запросов за день UTC, пока Broker работает (перезапуск сбрасывает счётчик). Это не денежный лимит и не список разрешённых тем: владелец ключа должен отдельно контролировать расходы у провайдера. Общий `state` повторяется для каждого item; не передавай личные материалы без прав.

Пример **синтетических**, не личных сообщений. Критерии здесь придуманы под конкретный запрос; для другой задачи составь свои:

```json
{
  "state": {
    "goal": "Найти сообщения о проблемах с ответами в Telegram-группах",
    "rule": "Считать прямым сигналом только описанную человеком задержку ответа"
  },
  "items": {
    "example-1": {"text": "Написал вчера, ответа до сих пор нет", "source": "synthetic"},
    "example-2": {"text": "Во вторник выйдет обновление", "source": "synthetic"}
  },
  "questions": {
    "is_delay_report": {
      "mode": "noul",
      "task": "Сообщает ли автор о фактической задержке ответа?"
    },
    "message_kind": {
      "mode": "choice",
      "task": "Какой тип у сообщения?",
      "options": {
        "complaint": "Жалоба на задержку",
        "question": "Вопрос о сроке ответа",
        "announcement": "Информационное объявление",
        "none_unknown": "Ни один вариант не подтверждён текстом"
      }
    },
    "research_value": {
      "mode": "score",
      "task": "Насколько текст полезен для исследования именно задержек ответа?",
      "rubric": [
        "0: не по теме",
        "1: косвенно связан, без описания случая",
        "2: конкретный случай задержки"
      ]
    }
  }
}
```

Ответ `items` содержит результаты по ID, ошибки и общую метаинформацию. Не считай пустые результаты или `all_failed` оценкой. При частичных ошибках используй только явно успешные элементы; не объявляй неизвестную стоимость нулём. Сопоставь каждую важную оценку с исходным материалом. JEV может ошибиться и не обязан быть лучше твоей собственной оценки — проверяй его пользу на размеченных примерах.

## Если задача пришла из Telegram

Telegram-клиент или отдельный инструмент сначала получает сообщения доступного чата и их ID/ссылки. Затем ты формулируешь вопрос и передаёшь подходящие записи в Broker. JEV не вступает в группы, не читает канал через Telethon и не пишет людям. Решение об ответе, публикации или другом действии остаётся в основной программе и её правилах доступа.

Передача в JEV полного текста, который ты **уже** загрузил в свой контекст, не экономит потраченные токены. Для настоящей экономии нужен отдельный поиск/адаптер, который отбирает кандидатов по ID, кратким выдержкам или метаданным **до** чтения полных сообщений агентом. Этот пакет такого Telegram-адаптера не устанавливает.

## Границы

Не передавай API-ключи, bearer-токены, пароли, cookie, файлы Telegram-сессий и иные данные входа. Для чужих переписок и клиентских материалов сначала проверь права и условия обработки; доступность чата технически не равна разрешению передавать содержимое внешнему сервису. Если нет достаточного контекста, сообщи о неопределённости и вернись к первоисточнику. JEV — помощник в выборе, не окончательный арбитр.
