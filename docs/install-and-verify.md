# Установка, проверка и откат

Эта инструкция рассчитана на Broker и Hermes **на одной машине с macOS или Linux**. Windows в этом выпуске не поддерживается. Пакет не открывает MCP в интернет: `scripts/run.py` допускает только `127.0.0.1:PORT`. Не направляйте внешний трафик на этот HTTP-адрес без отдельной TLS- и сетевой схемы.

Описанная установка предполагает доверенные профили Hermes под одним пользователем ОС. Раздельные MCP-токены позволяют отзывать доступ на уровне Broker, но **не скрывают файлы друг от друга**, если агентам доступно чтение произвольных файлов или shell под тем же UID. Для недоверенных профилей нужна отдельная изоляция ОС или хоста до выдачи доступа; не полагайтесь только на инструкции агенту и права `0600`.

## 1. Подготовка без платного вызова

Скопируйте репозиторий и перейдите в его папку (нужен установленный Git):

```bash
git clone https://github.com/AlekseiUL/jev-broker.git
cd jev-broker
go test ./...
python3 -B -m unittest discover -s scripts -p 'test_*.py'
go build -o bin/jev-broker ./cmd/jev-broker
python3 scripts/setup.py --profile assistant
python3 scripts/run.py --check
```

Добавьте `--profile another-agent` для каждого нового профиля **при первой настройке**. Укажите собственный ключ OpenRouter в скрытом приглашении `setup.py`, не в аргументах или чате. Скрипт не перезаписывает существующую приватную папку. Если она уже есть, остановитесь и разберитесь, прежде чем заменять ключи или права. Для пробной чистой установки можно задать `--home` на **новый, ещё не существующий** путь в приватном временном каталоге; не используйте реальный ключ для такого теста.

Ожидаемый результат `--check`: сообщение `Broker preflight passed`. Это проверка локальных файлов и бинарника, **не** проверка OpenRouter или качества JEV. `go test` использует моки, но первая загрузка зависимостей Go может потребовать интернет; платного вызова модели нет.

## 2. Запуск Broker

В другом терминале из корня пакета:

```bash
python3 scripts/run.py
```

Оставьте процесс работающим **всё время, пока агенты пользуются JEV**. Если порт занят, остановите конфликтующий процесс после проверки, что он действительно ваш. Не убивайте неизвестный сервис. `OPENROUTER_API_KEY` читает только локальный launcher из приватного файла; каждому Hermes-профилю нужен только свой bearer, а не ключ OpenRouter. После первого успешного ручного теста можно подключить свой менеджер процессов для автозапуска после перезагрузки. Шаблон системной службы здесь намеренно не ставится автоматически.

## 3. Подключение Hermes без вывода токена

Для каждого профиля выберите его **действительный** `.env` и `config.yaml`. У профиля по умолчанию это обычно `~/.hermes/.env` и `~/.hermes/config.yaml`; стандартный именованный `assistant` использует `~/.hermes/profiles/assistant/.env` и `~/.hermes/profiles/assistant/config.yaml`. Перед правкой узнайте реальные пути для вашего именованного профиля командами `hermes --profile assistant config env-path` и `hermes --profile assistant config path`. Если пути отличаются от примера, используйте выведенные пути. Для стандартного именованного `assistant`:

```bash
python3 scripts/install_profile_env.py --profile assistant --env-file "$HOME/.hermes/profiles/assistant/.env"
```

Скрипт читает `profile-assistant.env.fragment` из приватной папки, добавляет уникальную переменную в указанный `.env`, не печатает bearer и сохраняет приватную резервную копию прежнего файла. Если переменная уже есть с другим значением, он откажется перезаписывать её. Для другого профиля укажите его имя и **его** `.env`. Если несколько профилей намеренно используют один `.env`, их переменные всё равно различаются по именам.

В активный `config.yaml` этого же профиля вручную добавьте `jev_broker` из приватного `mcp-assistant.yaml`. В файле только ссылка `${JEV_BROKER_TOKEN_ASSISTANT}`, а не сам bearer. Если `mcp_servers` уже есть, объедините блоки под одним ключом. Сделайте локальную закрытую резервную копию `config.yaml` перед правкой; установщик его не меняет.

```yaml
mcp_servers:
  jev_broker:
    url: "http://127.0.0.1:8768/mcp"
    headers:
      Authorization: "Bearer ${JEV_BROKER_TOKEN_ASSISTANT}"
    tools:
      include: [evaluate]
```

Подстановка `${VAR}` в `headers` поддерживается [Hermes MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp). Убедитесь, что данный Hermes-профиль действительно загружает переменную из выбранного `.env`. Не вставляйте реальное значение в YAML, скриншот или отчёт.

## 4. Отдельно проверить `tools/list`

Перезапустите сеанс нужного профиля или выполните `/reload-mcp` в Hermes. Попросите агента показать **фактически зарегистрированные** MCP-инструменты и входную схему, не вызывая оценку; можно открыть `hermes mcp configure jev_broker` в соответствующей Hermes-среде. Ожидается один инструмент `mcp__jev_broker__evaluate` (именование зависит от версии Hermes), с `state`, `items`, `questions` и тремя режимами. Простая фраза агента «я знаю о JEV» не доказывает подключения — нужен live readback схемы.

`tools/list` не должен обращаться к OpenRouter. Если инструмента нет: проверьте, работает ли Broker, совпадает ли порт, тот ли `config.yaml` и `.env` использует профиль, нет ли второго `mcp_servers`, и не ошиблись ли в имени переменной. Не печатайте содержимое `.env` и не публикуйте диагностические журналы целиком.

Чтобы агент **сам узнавал, когда применить** инструмент, установите [скилл JEV Broker](../skills/jev-broker/SKILL.md) в папку `skills/` каждого нужного Hermes-профиля, как показано в [README](../README.md#как-дать-каждому-агенту-общую-инструкцию). В новом сеансе проверьте `/skills` отдельно от списка MCP-инструментов. Наличие скилла не заменяет подключение MCP, а наличие MCP само по себе не гарантирует, что агент прочитал правила применения.

## 5. Отдельный платный синтетический тест

Только после пункта 4 и явного решения владельца расходовать один запрос вызовите `mcp__jev_broker__evaluate` **один раз** с искусственным текстом и тремя вопросами:

```json
{
  "state": "Синтетическое сообщение: Написал вчера, ответа пока нет.",
  "questions": {
    "delay": {"mode": "noul", "task": "Есть ли здесь сообщение о задержке ответа?"},
    "kind": {"mode": "choice", "task": "Тип сообщения?", "options": {"complaint": "жалоба", "question": "вопрос", "none_unknown": "неясно"}},
    "importance": {"mode": "score", "task": "Полезность для исследования задержек", "rubric": ["не по теме", "косвенно", "конкретный случай"]}
  }
}
```

Ожидается структурированный ответ для всех трёх вопросов и метаданные попытки в закрытом журнале, но **не конкретные числа**. Не делайте вывод о точности инструмента по одному примеру. При сетевой ошибке не повторяйте платный запрос автоматически: сначала выясните, ушёл ли он к провайдеру.

## Откат и чистое удаление

Остановите Broker (`Ctrl-C`, если запускали вручную). Уберите **только** `mcp_servers.jev_broker` из затронутого `config.yaml` или восстановите его закрытую резервную копию. Уберите **только** соответствующую `JEV_BROKER_TOKEN_<PROFILE>` из `.env` или восстановите сохранённую резервную копию; остальные настройки Hermes не трогайте. Затем `/reload-mcp` и убедитесь, что инструмент исчез. Приватные файлы Broker не удаляются автоматически: перед удалением убедитесь, что они не нужны для отката и аудита. Если реальный ключ оказался раскрыт, немедленно отзовите его в OpenRouter и выпустите новый.

## Отзыв доступа конкретного профиля

Удаление MCP-блока или переменной из профиля **не отзывает украденный bearer**. Реестр `clients.json` загружается в память Broker только при запуске. Чтобы отозвать профиль: остановите Broker, сохраните закрытую резервную копию `clients.json`, удалите из него ровно запись нужного `id` вместе с `token_sha256`, проверьте корректность JSON и права файла `0600`, затем запустите Broker снова. У остальных профилей запись должна остаться. Если это был последний профиль, оставьте Broker остановленным до новой настройки: пустой реестр сервер не принимает. Уберите токен и MCP-блок из отозванного профиля, перезагрузите его MCP и проверьте, что доступ исчез; для оставшихся профилей проверьте `tools/list`. Не выводите bearer в терминал или отчёт. В этом выпуске нет автоматического редактора реестра; если вы не уверены в ручной правке, остановите Broker и сначала подготовьте новый приватный комплект для нужных профилей.
